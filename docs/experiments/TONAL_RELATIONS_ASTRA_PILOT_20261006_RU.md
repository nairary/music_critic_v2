# T04: первый Astra-assisted набор музыкальных отношений

Эксперимент: `EXP-TONAL-RELATIONS-ASTRA-PILOT-001`. Вопрос: удаётся ли из
доступных исходных версий собрать проверяемые отношения трёх типов с явными
участниками, интервалами и ограничениями? Ориентир — 12 произведений, по три
рок/поп/джаз/классика. Недоступность и недопуск сохраняются как результаты;
жанровые пограничные случаи указываются явно. Это намеренная пилотная выборка,
не репрезентативная оценка жанров и не оценка музыкального качества.

## Задачи и рубрика до чтения новых музыкальных данных

1. Внутри партии: восстановить конкретное созвучие, удержанный тон, надстройку
   и/или подготовку и разрешение. Одного chord symbol недостаточно для voicing.
2. Мелодия и меняющаяся гармония: назвать участвующие исходные ноты и интервалы
   гармонии; различать chord tone, extension и временную роль. Нота вне трезвучия
   сама по себе не ошибка. Не выводить слышимый аккомпанемент из chord symbols.
3. Между партиями: педаль, удвоение, противодвижение или передача материала
   требуют наблюдаемых участников обеих партий. Voice/staff не равны part.

Каждый случай содержит source-version ID, исходные event IDs, полуоткрытый
интервал и контекст; исходную шкалу времени (точные quarter-note fractions либо
измеренные секунды без подмены); ссылки на источник с bar/row/paragraph pointer;
source-backed утверждения отдельно от модельной интерпретации; альтернативы,
missing evidence и статус. Уровни: note, sonority, sequence/phrase, form, part.
Полный файл или несколько разобранных тактов не означают разметку произведения.

Рубрика каждого отношения: `source_supported` (в источнике есть трактовка и
привязка подтверждается), `astra_inferred` (модельная трактовка наблюдаемых нот),
`partial` (подтверждена только часть), `missing` (недостаточно данных), `rejected`
(проверяемая трактовка противоречит версии). Проверка механики и самостоятельная
перепроверка Astra не являются независимым экспертным gold. Все relation targets
имеют `target_available=false`, `confidence=null` до отдельной приёмки.

Простые диагностические ориентиры на тех же доступных событиях: состав
звучащего среза с учётом удержаний; членство MIDI pitch class в явно данном
chord-tone set (без угадывания quality); точное повторение/транспозиция с одним
масштабом времени; совпадение pitch class/октавы и направления движения между
явно известными партиями. Ответ правила, ответ Astra и причина расхождения
хранятся отдельно. Accuracy относительно Astra-разметки не есть экспертная
accuracy. Нейросети не запускаются.

## Допуск, бюджет и остановка

Перед payload — source-native metadata и известные work-family пересечения:
current split плюс native split. Любой known VALIDATION/TEST конфликт исключает
всё произведение. Чтение split metadata разрешено; нотные payload, изображения
и страницы PDF исключённых работ запрещены. Не читать общий HookTheory JSON.
Dilemma TRAIN разрешён по актуальному split manifest; PDMX/WJD/CoCoPops без
current TRAIN привязки — только `external_research_only` при отсутствии известного
heldout пересечения. Metadata-поиск не доказывает глобальное отсутствие дублей.

Сначала corpus-native кандидаты с доступными точными версиями. Не более 12 работ,
первых содержательных эпизодов на ось, 2 новых source downloads на допущенную
работу, суммарно не более 200 MB новых тел. Shared metadata downloads считаются
отдельно в accounting и также входят в общий byte cap. Родительские артефакты
перед использованием проверяются по terminal hashes. SQL WJD только read-only,
selected melids после admission. Никаких GPU, training, paid API calls, audio,
новых зависимостей, credentials, legacy, массовой разметки или model evaluation.

Выход: `outputs/tonal_relations_astra_20261006_001/` (ignored), per-genre receipts,
исходные bounded excerpts, annotations, rule diagnostics, coverage и hashes.
Annotation provenance: requested model `gpt-6-astra`, requested effort `ultra`,
agent ID, источник vs inference; фактическая backend API version неизвестна.
Отдельно отчёт в `docs/research/TONAL_RELATIONS_ASTRA_PILOT_20261006_RU.md`.
STATUS/ledger обновляет координатор. Старые terminal records не меняются.

## Условия завершения

Подтверждены существование и хеши использованных источников; все event IDs и
интервалы разрешаются; у каждого допущенного work есть admission receipt;
нет автоматически доступных targets; coverage считает только наблюдаемые
эпизоды. Missing оси остаются missing. Terminal запись отражает фактический
результат и ограничения, даже если 12 работ получить не удалось.
Следующий возможный этап — независимая экспертная разметка выбранных эпизодов
и согласование рубрики, а не автоматическое обучение на ответах Astra.
