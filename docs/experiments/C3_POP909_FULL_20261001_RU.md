# C3 relation gate: полный POP909-CL — 1 октября 2026

Выбранный C3 с relation gate на шаге **80 000** оценён на всех **908 принятых
произведениях POP909-CL**. Выполнены 1 816 предсказаний в двух заранее заданных
вариантах входа, без обучения и изменения весов. Время оценки — **930,65 с
(15 мин 31 с)** на CPU. Независимый пересчёт подтвердил метрики, матрицы
ошибок, маски, знаменатели, покрытие и исходные сплиты.

## Итоговые метрики

Native — основной результат с исходными MIDI-метаданными. Дополнительный
вариант убирает velocity, instrument program и channel, сохраняя время и высоты
нот. Accuracy рассчитана по событиям аккордов, macro-F1 — среднее F1 классов,
присутствующих в истинной разметке. Root означает основной тон, quality — тип
аккорда.

| Набор / вход | Root accuracy | Root macro-F1 | Quality accuracy | Quality macro-F1 | Root + quality accuracy |
|---|---:|---:|---:|---:|---:|
| Весь корпус, native | 89,78% | 0,8974 | 75,73% | 0,3612 | 72,61% |
| Весь корпус, без метаданных | 90,68% | 0,9066 | 78,56% | 0,3870 | 75,62% |

Мажорные и минорные трезвучия составляют 99 032 из 109 681 допустимых
quality-событий (**90,29%**). Поэтому accuracy заметно выше macro-F1:
редкие типы аккордов распознаются существенно хуже. Удаление метаданных
повысило все пять агрегированных метрик в этой оценке. Причина эффекта не
установлена; модель по нему не выбиралась и не настраивалась.

### Что известно о просадке C3 по типам аккордов

Просадка относится к quality на сопоставимом POP VALIDATION: macro-F1
0,453021 → 0,416032. Root macro-F1 вырос 0,908590 → 0,920000;
совместно правильно распознано 8 922 событий у C2 и 8 916 у C3 из 11 907.
То есть совместная accuracy отличается на шесть верных событий.

У редких типов выросли ложные срабатывания:

| Класс | Истинных событий | C2: верные / ложные распознавания | C3: верные / ложные распознавания |
|---|---:|---:|---:|
| Уменьшённое трезвучие (o) | 62 | 17 / 11 | 20 / 69 |
| Полууменьшённый септаккорд (/o7) | 28 | 15 / 37 | 17 / 102 |
| Малый минорный септаккорд (m7) | 611 | 287 / 663 | 198 / 485 |

Для первых двух классов C3 нашёл немного больше истинных примеров, но чаще
приписал эти классы другим аккордам. У m7 снизилось число верных распознаваний.
Macro-F1 даёт каждому из восьми наблюдаемых классов одинаковый вес;
поэтому потери редких классов влияют сильнее, чем на общую accuracy.
Снижение quality accuracy небольшое: 77,03% → 76,75%.

На исходной Dilemmadata VALIDATION у выбранных checkpoints quality macro-F1
был выше у C3: 0,478790 против 0,426443 у C2. Источник — hash-bound
`outputs/c3_threepass_final_review_001/analysis.json`, разделы best/per_head/quality,
закреплённые `EXP-C3-THREEPASS-FINAL-REVIEW-002`. Между корпусами различается
состав классов; здесь сопоставляется порядок моделей, не величина межкорпусного
падения F1. Улучшение на Dilemmadata не перенеслось на quality POP.

Точная причина не установлена. Более сильная подстройка под исходный корпус
и иной баланс локальных/контекстных признаков — гипотезы, не результат
контролируемой абляции. Различаются также batch и число optimizer updates:
C2 выбран на 115k при batch2 (230k предъявлений), C3 — на 80k при batch4
(320k предъявлений). По одним этим числам нельзя объявлять C3 недообученным.
Один seed и разные режимы не позволяют приписать просадку именно relation gate.
Удаление метаданных не устраняет порядок моделей по quality macro-F1:
C2 0,512451, C3 0,452281. Нужна отдельная контролируемая проверка механизма;
новый прогон в рамках этого объяснения не запускался.

## Предобъявленный протокол

Пользователь запросил весь POP909 и подтвердил cloud C3 с тремя проходами
и relation gate, шаг 80 000. Best = final по Dilemmadata VALIDATION;
checkpoint не выбирается по POP. SHA-256:
`d651511441907d4d559d0d3009c925107b9e371ca462db953f189ad4528e4a35`,
58 805 104 байта. Existing `critic.c3_backbone` loader проверяет bytes,
полный envelope, source, config, model contract и state; optimizer/RNG
не восстанавливаются.

POP909-CL закреплён на commit `be9094392903c471a930519e1c0bacf8b6be5d62`.
Все **908 принятых файлов** совпали по SHA с прежним индексом: 701 TRAIN,
101 VALIDATION, 106 TEST. Исходный 172 сохраняет прежний карантин;
новой фильтрации по результатам нет. Полный запрос разрешает TEST только
POP909-CL; Dilemmadata TEST закрыт. Подбор модели по TEST запрещён.

Root: softmax 37 орфографических классов суммируется по 12 pitch classes.
Quality: argmax всех 17 классов; допустимые gold — прежний subset9.
Неподдерживаемые/неоднозначные цели маскируются; outside-subset prediction
остаётся ошибкой. Macro-F1 — среднее по классам с наблюдаемой gold-поддержкой.
Сохраняются accuracy, confusion, per-class support/F1, coverage и joint accuracy.

Для сопоставимости с прежней оценкой C0/C2 используются конечные C3 logits
на **raw beat candidates**, не base logits и не slice readout. Каждое исходное
chord event по точному рациональному началу относится к содержащему его
полуоткрытому beat. Несколько аккордов одного beat остаются отдельными событиями.
Native — основной вид; metadata_removed — заранее заданный дополнительный.
Channel 1 служит только источником целей и исключён из raw graph. Цели
открываются после предсказаний обоих видов входа.

Исполнение локальное CPU, FP32, один поток, ноль обновлений весов.
Отчёт показывает весь корпус и каждый исходный split отдельно.
Это две гармонические задачи, не эстетическое качество и не все 18 голов.
Полный межкорпусный поиск дубликатов не выполнен.
