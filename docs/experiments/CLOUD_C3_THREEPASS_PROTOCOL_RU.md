Первый и второй проходы обновляют note/onset/beat/bar/slice. Последний —
note/beat/slice, используемые выходными головами. Это обеспечивает возможность
пути note → slice → bar → slice. Топология и raw-признаки не меняются.

Relationgate вычисляет отдельный score из текущего представления получателя
и агрегированного сообщения каждого типа. Softmax применяется только к
непустым типам у этого получателя. Веса умножаются на число непустых типов:
при нулевых начальных scores получается прежняя сумма. Пустые типы имеют
нулевой вклад; узлы с единственным возможным типом не требуют обучаемого выбора.
Gate зависит от события; gold-labels и музыкальные роли во forward не подаются.
Все общие параметры пары инициализируются одинаково; gate-параметры создаются
после них. Это не смесь mean/attention и не прежний task/logit fusion.

Стабильные ID: `EXP-CLOUD-T4-C3-{THREEPASS,RELATIONGATE}-{MEMORY,GATE,80K}-001`.
До GPU-вычислений обязательны source/config/data bindings и planned records.
Каждая VM отдельно проходит native CPU tests, memory ≤ 6 forwards / 0 updates
и 32-update / 128-draw all-shift / full-resume gate. TRAIN стартует только после
успеха. Validation каждые 5k, checkpoints каждые 1k. Best выбирается по прежнему
common-support primary macro-F1 восьми основных голов; сохраняются все 18 голов.

Сравнение relationgate ↔ threepass изолирует выбор типов при прочих равных.
Сравнение с текущим двухпроходным C3 attention оценивает глубину при одинаковых
batch/draws, с оговоркой разных VM и исходников. Новая пара не сохраняет все
исторические начальные Q/K веса двухпроходной модели: дополнительный слой
меняет расход RNG до их создания. Контроль mean × 3 не запрошен; взаимодействие
глубины и внимания этим дизайном полностью не изолируется. Исторические B2
результаты показываются отдельно по updates и draws.

История подготовки до разрешения запуска: запрос квоты `atdp6lumo7qj2ujgq56m`; T4 × 4, 64 CPU и 256 GiB RAM одобрены,
400 GiB SSD ещё обрабатываются. Новые VM не созданы. Действующие модели
не прерываются. Новая обычная пара стоит примерно 221,19 ₽/ч. Черновые лимиты
44 ч TRAIN / 46 ч VM после deployment плюс до 2 ч bootstrap дают до 10 617 ₽
на новую пару. Остаток гранта около 11,6 тыс. ₽ также должен покрыть текущую
пару и хранение. Ответ по допустимому бюджету ожидается; эти лимиты не являются
разрешением оплачиваемого перерасхода. Четыре SSD по 100 GiB стоят около
5731 ₽ за 720 часов даже после остановки VM. Краткий резерв 500 ₽ не покрывает
месяц хранения. Экспорт — в существующий приватный бакет, уникальные префиксы,
затем остановка VM. Старые лимиты 70/72 ч на новые варианты не переносятся.

Не входят: TEST, новые датасеты/targets, изменение historical transposition,
JEPA/SSL, MMoE/task fusion, mean+attention смесь, ширина > 128, public GitHub,
слияние с main или изменение текущих моделей. Legacy не используется.

Предварительная локальная проверка: код реализован; объединённая CPU-проверка 22 файлов: **494 passed**,

и обучение ещё не запускались; бюджет и SSD остаются условиями запуска.
