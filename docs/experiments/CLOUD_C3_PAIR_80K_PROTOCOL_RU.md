`temporal_slice_c2` — техническое имя контрольной модели с точными временными
событиями; это не старая C2 без temporal-ветки. Внимание здесь относится к
обмену информацией между временными узлами. Это отдельный эксперимент от
прежних logit fusion, task-attention fusion и MMoE.

Обе модели получают одинаковые графы, транспозиции, порядок произведений,
границы батчей, цели и расписание обучения. Общие параметры инициализируются
одинаково; новые параметры внимания существуют только во второй модели.
Сохраняется исторический C2-путь транспозиций, включая прежние track pitch
summaries: их исправление не добавляется как второй фактор этой абляции.
Отличается оператор обмена сообщениями; число параметров и время обучения
могут различаться. Это сравнение при одинаковом числе обновлений и примеров,
а не при одинаковом времени GPU.

Перед каждым длинным запуском выполняются отдельно зарегистрированные
проверки на его GPU: память (не более 6 forward/backward, ноль optimizer
updates), затем 32 updates / 128 draws с проверкой всех 12 shifts и полного
resume. Неуспешная проверка останавливает цепочку до обучения. Для каждого
этапа сохраняются исходный код, конфигурация, хеши данных, окружение и
отдельная запись эксперимента; неудачные попытки не перезаписываются.

TRAIN ограничен 70 часами; отдельный таймер VM — 72 часами с момента
установки защиты. После завершения или ошибки выполняются экспорт результатов
в приватное Object Storage и остановка VM. Диск сохраняется при ошибке
экспорта. Крупный архив разбивается на части до 2 GiB с SHA-256 частей и
полного архива; маркер COMPLETE появляется только после проверки загрузки.
Перед запуском проверяются свободное место и право VM остановить себя.

Закрыты TEST, новые датасеты, changes-цели, SSL/JEPA, MMoE и task fusion.
Legacy не используется. Прогон с batch 4 получает вдвое больше примеров,
чем исторические 80k с batch 2: историческая кривая остаётся контекстом,
а причинное сравнение внимания проводится между двумя новыми моделями.
Один seed не позволяет утверждать статистическую значимость.

80k — примерно 31.25 часа только обновлений, без validation и экспорта.
