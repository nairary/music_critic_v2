# Батч 4 и восемь воркеров на T4: короткий замер

Дата: 2026-09-17. Эксперименты `EXP-CLOUD-T4-BATCH4-MEMORY-001`,
`EXP-CLOUD-T4-BATCH4-GATE-001`, `EXP-CLOUD-T4-BATCHSIZE-BENCH-001` и независимый
импорт `EXP-CLOUD-T4-BATCHSIZE-RESULT-001` завершены.

## Скорость

Обычная T4, 16 vCPU, 64 ГиБ RAM; temporal-модель без внимания, FP32,
`coalesced_reference`, `pipeline8`. Восемь воркеров, девять ожидающих батчей,
8 ГиБ суммарного кеша в обоих вариантах. Один элемент батча — произведение.

| Вариант | Секунд / update | Произведений / с | Секунд на одинаковые 400 произведений |
|---|---:|---:|---:|
| Батч 2, 8 воркеров | 0.890344 | 2.246322 | 178.069 |
| Батч 4, 8 воркеров | 1.406200 | 2.844547 | 140.620 |

Отношение пропускной способности B4/B2: **1.2663×**;
изменение произведений/с: **+26.63%**;
сокращение времени на одинаковый объём данных: **21.03%**.

Каждый вариант получил одинаковый поток из 600 произведений с теми же
транспозициями: первые 200 — прогрев, следующие 400 — измерение.
B2: 100+200 updates; B4: 50+100 updates. Суммарно 450 updates / 1200 draws.
Начальные model/gradients/optimizer/scheduler/scaler/RNG fingerprints совпали.
Измеряется сумма времени полных обновлений с синхронизацией GPU, включая
ожидание данных. Это один короткий прогон в порядке B2 → B4, без повторов;
кеши рабочих процессов свежие, системный файловый кеш не сбрасывался.

## Память и корректность

- Выбранные крупнейшие TRAIN-графы: 5 B4 forward/backward,
  без optimizer updates, с резервом памяти под два состояния AdamW.
- Максимум CUDA allocated: 4.565 ГиБ;
  reserved: 5.236 ГиБ; лимит: 12 ГиБ.
- Отдельный native gate: 32 updates / 128 draws, все 12 транспозиций,
  совпадение с контрольным вычислением и точный full resume со свежими очередями.
- 302 локальных и 307 native CPU fixture-тестов прошли; одно прежнее
  предупреждение PyG на suite. Helper-тесты: 10; verifier-fixtures: 14.
- Все 74 файла экспорта сверены с manifest;
  checkpoint проверен по SHA-256 без загрузки тензоров.
- TRAIN использовался для вычислений; VALIDATION — только membership metadata.
  VALIDATION inference и TEST не запускались. Это проверка source-bound
  журналов/деклараций, без системной трассировки доступа к файлам.

## Вывод и границы

Батч 4 технически работоспособен в проверенном temporal runtime.
Он повышает пропускную способность в данном замере.
Проверка памяти охватывает выбранные тяжёлые графы, а не все возможные батчи.
Уменьшение числа шагов при том же количестве произведений меняет градиенты,
потребление dropout RNG и продвижение optimizer/LR; качество здесь не оценивалось.
80k updates при B4 содержат вдвое больше draws, чем 80k при B2. Для проверки
внимания нужны одинаковые batch size, данные, seed и бюджет у внимания и контроля.
Наследуемый горизонт scheduler 120k был фиксирован для speed-screen; будущий
B4 training schedule этим запуском не выбран. Длинное обучение не запущено.
