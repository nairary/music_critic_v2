# C4 → Dilemmadata: обратный перенос после обучения на POP909-CL

Запрос пользователя: после завершения C4 оценить его на Dilemmadata и
сопоставить с сохранённым C3, обученным на Dilemmadata и оценённым на POP909-CL.
C3 повторно не запускался. Статус: **обучение и обратная оценка завершены**.
Запись оценки — `EXP-C4-DILEMMA-TRANSFER-001`, `completed`, код выхода 0.
Все 162 произведения оценены за 86,632 с; 0 обновлений, веса неизменны.
Выбран финальный шаг C4 80 000, совпадающий с лучшим по POP VALIDATION.

## Результат

| Модель и выборка | Root accuracy | Root macro-F1 | Quality accuracy | Quality macro-F1 | Root+quality вместе |
|---|---:|---:|---:|---:|---:|
| C3 → POP VALIDATION101, прежний результат | 92,31% | 92,00% | 76,75% | 41,60% | 74,88% |
| C4 → POP VALIDATION101, обучение завершено | 94,23% | 93,98% | 87,84% | 43,33% | — |
| C4 → Dilemmadata VALIDATION162, общий gold subset9 | 53,78% | 49,34% | 47,07% | 15,71% | 32,91% |
| C3 → POP полный908, прежний результат | 89,78% | 89,74% | 75,73% | 36,12% | 72,61% |

Root — классы высоты, quality — тип аккорда. Проценты F1 сохраняют прежнее
усреднение по классам с истинной поддержкой. В POP VALIDATION quality имеет
8 наблюдаемых классов, в общем Dilemmadata subset9 — 9. Predicted argmax
всегда берётся по всем 17 выходам; лишние классы не отбрасываются.
Сравнение двух направлений переноса описательное: проверочные корпуса разные.
У C4 на POP VALIDATION среднее root/quality F1 выросло с C3 66,80% до 68,66%;
это выбранный на той же POP VALIDATION checkpoint, а не новый TEST-результат.
На Dilemmadata обратный перенос C4 существенно слабее прежнего C3 → POP.

Главная таблица использует общий gold subset9. На всех допустимых
Dilemmadata quality целях полный17 результат ещё ниже: accuracy **46,85%**,
macro-F1 **8,82%** по 16 наблюдаемым классам. В общий subset9 не вошли 690
событий из 151 927 quality-eligible. Это не объясняет всю потерю переноса:
на самом общем subset9 macro-F1 тоже только 15,71%. Причина падения этим
одним экспериментом не установлена.

## Зафиксированный протокол

- C4: лучший checkpoint по POP VALIDATION после завершения исходных 80 000
  updates. Dilemmadata не используется для выбора checkpoint или изменения весов.
- Проверочная выборка: все 162 записи закреплённого Dilemmadata VALIDATION,
  без транспозиций. TEST закрыт. TRAIN музыкальные payloads не читаются.
- Вход и временные узлы — только raw canonical piece. После предсказания
  исходные harmonic events присоединяются к существующим raw beats по
  закреплённым source relations. Кратность событий сохраняется.
- Root и bass: вероятности написаний суммируются в 12 классов высоты, как
  при обучении C4 и прежней POP-оценке. Quality: полный argmax17; отдельно
  все допустимые Dilemmadata-цели и общий с POP gold subset9. Предсказания
  вне subset9 остаются ошибками. Отдельно считаются inversion и PCS93.
- Маски доступности, принадлежность словарю и выравнивание считаются независимо.
  Macro-F1 усредняется по классам с истинной поддержкой, рядом сохраняются
  accuracy, confusion, поддержка каждого класса и число исключённых событий.
- Исторический основной comparator: C3 native POP VALIDATION101 из
  `EXP-POP-C3-FULL-EVAL-002`. Его полный POP908 результат приводится отдельно,
  не смешивается с 101-произведением. Повторного C3 inference нет.
- Лимит: 162 model forwards, 0 updates, максимум 3 600 секунд. Исходники
  evaluator отделены от неизменяемого снимка обучения C4 `source002`.

Разные проверочные корпуса, состав классов и доступные метки не позволяют
трактовать разницу абсолютных F1 как причинное превосходство C4. Нужный
пользователю ответ — численное сопоставление двух направлений переноса,
с явным покрытием. Это распознавание гармонических целей, не человеческая
оценка музыкального качества. Тринадцать не обученных на POP голов не оцениваются.

`scripts/evaluate_c4_dilemma.py`, `tests/experiments/test_c4_dilemma_transfer.py`.

не восстанавливаются. Запуск проверяет собственный implementation fingerprint,
planned record, request fingerprint и declared access policy до payloads.

и **25 passed** на родном сервере. По одному существующему предупреждению
PyG/Torch; ошибок нет. Независимые Standards и Spec reviews завершены без
замечаний после исправления guards и независимого покрытия.
Legacy не использовался, новых зависимостей нет.
