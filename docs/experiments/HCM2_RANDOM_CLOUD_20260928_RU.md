# HCM-2 со случайным обучаемым C3: облачный запуск

28 сентября 2026. Пользователь выбрал один запуск с нуля на 10 000 обновлений
в Яндекс Облаке и принял ограничения сравнения с текущей веткой на 3090.

## Что запущено

`EXP-HCM2-RANDOM-T4-TRAIN-002` стартовал 28 сентября в 22:05:33 МСК.
На 22:08:50 подтверждены 8 обновлений; процесс 1792 работает на T4,
ошибок в stderr нет. В фактическом `training-binding.json` указаны
`random_initialization`, `warm_start=null`, `freeze_policy=full` и
`freeze_local=false`. C3 и новый декодер обучаются вместе. Неиспользуемые
теоретические головы остаются замороженными. Архитектура — прежние 20,6 млн
параметров; проект расширения до 160 млн сюда не включён.

Обучение на 3090 не изменялось. Это сравнение двух способов подготовки модели,
а не чистое измерение пользы предобучения C3: ветка на 3090 получила также
декодер HCM-1, замороженный энкодер и другое расписание обучения.

## Данные и настройки

Используются те же 700 полных TRAIN-песен POP909-CL, что на 3090.
Все файлы сверены по хешам. Fingerprint исходного манифеста:
`b977f361bbcba9a976a14e67fbdb7aff3cc211beb8a5009c9022da6b70414a70`.

- Seed: 20260928. Маски: 1, 2 или 4 такта; вероятности 0,5 / 0,3 / 0,2.
- Вероятность маскирования одной дорожки: 0,5.
- `pretrained`, `warm_start`, `resume`: null. Веса из аппаратной проверки не переносятся.
- LR энкодера и декодера: 2e-4; warmup 50 шагов, затем cosine до 10 000.
- Сохранение каждые 250 шагов и при штатном завершении или обработанном SIGTERM.
- Данные Dilemmadata/PDMX не добавляются. VALIDATION/TEST не разрешены этим запуском.

LR случайного C3 повышен с прежнего значения 2e-5 для дообучения: новая ветка
не должна сохранять ранее приобретённые представления. Это дополнительное
различие с веткой на 3090. Частота сохранения оставляет место на существующем
диске; перед развёртыванием было около 29 GiB свободного места. Старые
чекпоинты и результаты не удалялись.

## Аппаратная проверка и неудачная попытка запуска

`EXP-HCM2-RANDOM-T4-GATE-001` завершён успешно за 263,15 секунды.
Три TRAIN-примера проверили обычную, длинную и плотную песню. CPU/GPU NLL
и градиенты согласуются в заданных допусках. Возобновление проверено тремя
физическими обновлениями, соответствующими двум логическим шагам.
Максимальное различие весов после возобновления — 2,92e-8; это не побитовое
тождество. Пик зарезервированной GPU-памяти — 1 400 897 536 байт (1,30 GiB).
Шаги заняли 21,37 / 22,61 / 20,45 секунды. Это не доказательство вместимости
всех возможных примеров корпуса и не оценка качества модели.

В `src/music_critic/pll/cloud.py` для eval-проверки градиентов GRU локально
отключён cuDNN: его RNN evaluation не сохраняет буфер для backward.
До настоящих обучающих шагов прежний backend восстанавливается. Регрессионный
тест проверяет обновление локальных весов случайного C3, неизменность
теоретических голов, восстановление backend и resume.

`EXP-HCM2-RANDOM-T4-TRAIN-001` завершён как failed: предварительная проверка
отклонила отформатированный JSON записи вместо канонического представления.
Тренер не запускался, обновлений — ноль. Исходные байты записи и журнал
сохранены. Формат исправлен, registry и нативная предварительная проверка
повторно пройдены; основной запуск получил отдельный ID TRAIN-002.

Независимые Standards/Spec-проверки кода и запуска выполнены. Замечания о
таймере подготовки и слишком коротком сроке действия конфигурации исправлены.
После исправления формата записи повторно проверены её каноничность, хеши
и соответствие реальным настройкам. Проверки:

- `tests/pll/test_cloud.py tests/pll/test_whole_runtime.py tests/pll/test_encoder.py`:
  29 passed, 1 существующее предупреждение PyG, 11,95 секунды.
- `tests/critic/test_server_runner.py`: 35 passed, 1,57 секунды.
- Реестр: 233 записи прошли проверку перед повторным запуском.

Legacy не использовался; новые зависимости не добавлялись.

## Время, расходы и остановка

Используется одна существующая прерываемая T4 VM `fhmrp02s0adbjtene7s8`,
16 vCPU и 64 GiB RAM. Перед стартом GPU была свободна. Остальные три VM
оставлены остановленными. Первые два настоящих обновления заняли 22,82 и
22,02 секунды: ориентир — около 60 часов, но это очень маленькая выборка.
Срок не гарантирован, особенно с учётом возможности прерывания VM.

Тарифный ориентир для вычислений: 17,56 + 16×0,3184 + 64×0,0768 =
27,5696 ₽/час. Консервативная оценка с диском и адресом — 36 ₽/час.
[Официальные тарифы](https://yandex.cloud/ru/docs/compute/pricing).
Денежный баланс и фактическое списание не измерены.

Для нового опыта задано 69 часов от первого включения VM, то есть
2484 ₽ по принятой оценке, в пределах расчётного бюджета 2500 ₽.
Абсолютный таймер выключения: **1 октября 18:40:58 МСК**. Обучающий процесс
имеет собственный предел 68 часов и 120 секунд для штатного завершения.
При успехе или ошибке службы VM выключается сразу. Автоматического
перезапуска нет; постоянный диск сохраняет результаты и может продолжать
тарифицироваться после выключения VM.

Первый вызов старого API-helper вернул HTTP 401. Резервное выключение через
ОС привело к подтверждённому провайдером STOPPED. Поэтому во второй попытке
вызов API исключён, его таймер отключён; используется проверенное выключение
через ОС. Независимый root-таймер имеет проверенную абсолютную дату.
Таймеры завершённого HCM-1 и временный таймер подготовки отключены.
