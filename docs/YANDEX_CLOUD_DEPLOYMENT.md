## Самый простой порядок переноса

1. Сохранить приватный снимок текущего кода с файловым SHA256-манифестом:
   рабочее дерево содержит незакоммиченные изменения, поэтому одного git clone
   недостаточно. Не включать .git, .env, ключи, данные, outputs и виртуальное окружение.
2. Восстановить доступ к исходному GPU-серверу или найти другую точную копию
   подготовленных данных. Копировать только файлы из TRAIN/VALIDATION-манифеста,
   проверяя размер и SHA256. Не пересобирать подготовленные данные молча.
3. Для хранения создать приватный STANDARD-бакет Object Storage. Загружать
   архив кода и версионированные архивы данных с контрольными суммами.
   Передавать напрямую с исходного сервера, если доступ позволяет; Mac может
   быть промежуточной точкой. Для возобновляемой загрузки подходят rclone/AWS S3.
   Никакая VM для хранения в бакете не нужна.
4. Только когда понадобится обучение: выбрать бюджет и доступную GPU-квоту,
   создать Linux GPU VM, скачать набор на её диск и сверить все хеши.
   Object Storage служит для переноса/сохранения, рабочие данные читает локальный
   диск VM. Результаты и checkpoints возвращаются в отдельный префикс бакета.
5. Перед реальным прогоном зарегистрировать новый эксперимент и пройти новые
   environment/equivalence/memory gates. Старый GPU gate нельзя использовать:
   runner привязывает его к GPU, Python, Torch/CUDA и другим параметрам среды.

## Окружение требует отдельной подготовки

Сохранённый successful temporal gate использует Python 3.12.8,
Torch 2.2.2+cu118, NumPy 1.26.4, torch-geometric 2.6.1, RTX 3090.
При этом текущий `pyproject.toml` требует Torch >=2.8 и torch-geometric >=2.7.
Поэтому `pip install -e .` не воспроизводит проверенное экспериментальное
окружение автоматически. Следующий deployment task должен явно выбрать
зафиксированную среду или валидировать новую; менять зависимости сейчас не стали.
Манифест данных содержит абсолютные Linux-пути: при переносе нужен новый
производный манифест с прежними SHA256 payload и ссылкой на исходный манифест;
исходный файл и терминальные записи сохраняются неизменными.

## Стоимость хранения, без обучения

По опубликованным тарифам STANDARD: 2.376 руб./GiB в месяц, включая НДС.
Первый 1 GiB, 10 000 операций записи/LIST и 100 000 чтения в месяц бесплатны
в пределах соответствующего free tier; его доступный остаток не проверен.
Для полного месяца и доступного первого бесплатного GiB:

| Объём | Только хранение в месяц |
|---|---:|
| 20 GiB | 45.14 руб. |
| 40 GiB | 92.66 руб. |
| 100 GiB | 235.22 руб. |

Это ориентиры до сжатия, операций и возможного интернет-egress. Входящий
трафик и передача между сервисами Yandex Cloud не тарифицируются; у исходящего
интернет-трафика Object Storage есть бесплатные первые 100 GiB/месяц.
Покрытие Object Storage данным грантом и остаток гранта не проверены.
Не использовать ICE для краткого ожидания: у него минимальный платный срок год.
