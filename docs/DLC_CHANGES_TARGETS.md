## Что предсказывать

Цель — множество атомарных обозначений из `changes`. Например:

| Источник | Положительные классы |
|---|---|
| `64` | `6`, `4` |
| `^4^2` | `^4`, `^2` |
| `139` | `13`, `9` |
| `+b9-3` | `+b9`, `-3` |
| `b3` при `chord=Ger6` | `b3` |
| пустое поле при подтверждённой валидной аннотации | пустое множество |

Модификаторы могут присутствовать одновременно: это multilabel-задача.
`64` не задаёт временную последовательность разрешений. Отдельно сохраняются
исходный порядок, повторы, числовой интервал, альтерация и префикс каждого атома.
`+` обозначает добавление, `-` пропуск; `^`/`v` влияют на трактовку замены.
Непомеченные интервалы не переименовываются автоматически в реальные задержания.
Лексическая грамматика допускает числа 0–19, как источник; это не доказательство
музыкальной интерпретации каждого сочетания. `2` и `9` остаются разными классами.

Парсер следует лексическому правилу [ms3 `changes2list`](https://raw.githubusercontent.com/johentsch/ms3/main/src/ms3/utils/functions.py),
но требует полного разбора строки. Музыкальная нотация описана в
[официальном справочнике DCML](https://dcmlab.github.io/standards/build/html/reference/reference.html#suspensions-and-retardations).
Код ms3 не импортируется и не исполняется. Использованная upstream-страница
`main` не является закреплённой версией зависимости; локальный парсер фиксируется
собственным кодом, тестами и хешем в записи эксперимента.

Сохраняем исходное `changes`, `chord` и контекст. Для `Ger6` раскрытие `b3`
документировано. Предварительное объяснение `IM7 → ^#8` как нормализации
не подтвердилось: новый alignment-gate маскирует такое необъяснённое соответствие.

## Маски и привязка

- Единица выгрузки: `record_id + unfolded_harmony_index`, одна исходная
  аннотация с перечнем строк TSV. Повторение на нотах не увеличивает поддержку
  класса. Это число аннотаций, не обязательно число смен гармонии.
- `target_mask=true` требует единого разбираемого `changes`, непротиворечивого
  контекста, непустого аккорда, известного ID и `valid_chord_label=True` на всех
  строках группы. Иначе сохраняем причины и маскируем всю группу.
- Пустая строка становится отрицательным supervision только после этих проверок
  и только в данном контракте расширенных DLC-аннотаций. Отсутствующее поле,
  `None`, `NaN`, невалидная метка или неразобранный текст не становятся негативами.
- Словарь строится только по unmasked TRAIN-аннотациям. `positive_tokens` —
  разреженное представление; `encode_presence` выдаёт multi-hot и маску. Если
  внешний пример содержит неизвестный атом, вся его цель маскируется.
- Сохраняются хеш файла, component/split, строки, исходный контекст и первый
  наблюдавшийся нотный onset как точная дробь. Это точность записи источника,
  а не восстановление информации, которую источник мог округлить.
- `a_isOnset` сохраняется как свидетельство источника. Его отсутствие не
  доказывает отсутствие аннотации: повтор гармонии может иметь `False`.
  Временные границы и длительности аннотации не выдумываются.
- `canonical_alignment_status=not_performed`: присоединение к существующим
  raw-note/beat кандидатам ещё не выполнено. Эти sidecars нельзя просто подать
  в текущий loss без адаптера выравнивания. Gold-сегментация и targets не должны
  участвовать в построении графа или выборе prediction positions.

## Воспроизведение и границы

```bash
PYTHONPATH=src /private/tmp/music-critic-pilots-20260913/bin/python \
  scripts/prepare_dlc_changes_targets.py \
  --manifest outputs/changes_train_census_001/manifest.json \
  --output outputs/changes_train_targets_NEW
```

Использовать установленное окружение проекта: существующий `tasks/__init__.py`
импортирует torch-geometric. Новых зависимостей не добавлено. TRAIN-membership
манифеста установлена по фактическим draws в сохранённом training snapshot;
сам экспортёр проверяет декларацию TRAIN всех записей до чтения payload,
безопасность путей и хеш/размер каждого исходного файла. Он не заново вычисляет
сплит. Произвольный чужой манифест сначала требует независимой проверки membership.

Выход: `events.jsonl`, `vocabulary.json` с поддержкой по аннотациям и произведениям,
копия `manifest.json`, итоговый `receipt.json`. Существующий выход не перезаписывается;
неуспешная попытка сохраняется без completed receipt. Все полные данные в ignored
`outputs/`. TRAIN-словарь не является общей гармонической онтологией для HookTheory/POP.

Проверка небольшой музыкальной выборки, выравнивание с raw-кандидатами и
транспозиции реализованы в отдельном `DLCChangesAlignment@1.1.0`; исходная выгрузка
не переписывалась. Следующий этап — дополнительная голова и сравнение.
Метки «какая нота подготовлена,
задержана и куда разрешилась» требуют отдельного анализа голосов и времени;
этот экспорт их не создаёт. Качество распознавания и критики ещё не измерялось.
