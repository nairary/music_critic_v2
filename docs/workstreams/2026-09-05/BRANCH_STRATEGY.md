# Main и ветка разработки — 2026-09-05

Пользователь решил сохранить этап готовых C0/C1 в main и вынести четыре новых
направления в отдельную developer-ветку, созданную от main. Это заменяет прежнее
решение о размещении разработки непосредственно в main.

| Ветка | Состояние и назначение |
| --- | --- |
| `main` | Опубликованная база `f0e0886161c9f67786011508006db61c803c1752`, до четырёх workstreams. |
| `codex/develop` | Разработка от этой базы, включая все четыре принятые реализации и последующие документы. |

В исходной базе уже есть завершённые C0/C1 на 10k обновлений и C2 на 120k.
Запись C0-120k всё ещё ожидает первичных итоговых свидетельств. Ветки обозначают
состояние исходников; они не подтверждают завершение обучения или качество модели.

Сначала `codex/develop` создана на точном SHA опубликованного main, затем
продвинута fast-forward до принятого merge
`849abd601f6d1faa7d429cf1c62600f60ade5f4c`. После проверки сохранности этих коммитов
только локальный main возвращён к исходному SHA. Принятый source commit
`a628af4bb72358f0ca99ad1a8c04fcf4a78cc845`, merge, исходные worktrees и recovery
stash сохранены. Revert, hard reset, удаление истории и force-push не применялись.

34 implementation/test/config/CLI файла совпадают с

814 passed, 6 CUDA skips, 2 deselected, 2 upstream warnings in 52.87s — остаётся

fingerprints, JSON, локальные ссылки и whitespace; новый тестовый запуск не нужен.

Разрешённая публикация: `refs/heads/codex/develop` в существующий публичный
[nairary/music_critic_v2](https://github.com/nairary/music_critic_v2).
Удалённый main остаётся на исходном SHA. Эта ветка публикует проверенные код,
тесты, конфигурации и документы; датасетов, checkpoints и generated artifacts
в изменениях нет. Текущий workflow автоматически запускается для main и pull
requests; сам push новой developer-ветки не означает новый запуск полного CI.

Дальнейшие задачи стартуют от `codex/develop`; принятые изменения собираются там.
Переход следующего этапа в main — отдельное решение пользователя после ревью
совместной версии и её проверок. Эксперименты на реальных данных требуют своего
протокола и записей; TEST, активное C0, SSH и legacy этим шагом не затрагиваются.
