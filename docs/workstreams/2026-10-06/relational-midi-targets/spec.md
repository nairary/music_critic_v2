# Таргеты музыкальных отношений для событий датасета

Фаза T05, 6 октября 2026. Пользователь уточнил требуемый результат: новые
структурированные targets у MIDI/canonical событий, пригодные для загрузки
как вспомогательная разметка. Текстовые карточки T04 этого не обеспечивали.
Запрос разрешает принять явно обозначенную разметку Astra как weak supervision;
независимая человеческая верификация не является условием наличия такой метки.
Отсутствие экспертного gold и неизвестная численная confidence сохраняются.

## Выпускаемый результат

На основе неизменяемого `EXP-TONAL-RELATIONS-ASTRA-PILOT-001` выпустить новый
слой для трёх уже допущенных current TRAIN произведений: Mozart K283-I,
Mendelssohn Op12-I, Pleyel B309-I. Остальные девять версий не имеют доказанного
соответствия каноническим MIDI-событиям TRAIN и получают явную причину исключения
из этого выпуска. Не присваивать внешним событиям вымышленные canonical IDs.

Каждое назначение содержит canonical piece/note IDs, исходные event IDs,
тип флага, точный подынтервал звучания, relation ID, связанные canonical notes,
версию источника и происхождение интерпретации. Контекстные ноты не получают
положительный флаг автоматически. Связанное продолжение остаётся подынтервалом
одной канонической ноты, а не новой атакой. Source Part сохраняется отдельно:
существующий DLC canonical track не равен инструментальной партии.

Первый фиксированный словарь: `held_common_tone`, `resolving_chordal_seventh`,
`resolution_arrival`, `anticipation`, `anticipated_arrival`, `contrary_ascending`,
`contrary_descending`, `octave_upper`, `octave_lower`. Astra назначает роли
отдельным событиям из сохранённых нот и разбора, без автоматического парсинга
текста как gold. Note×harmony факты сохраняются отдельно от этих ролей.

Для существующего загрузчика создать opt-in registry extension и настоящий
`TargetBundle@1.0.0`: девять задач `theory.relations.<flag>`, note alignment,
categorical `absent/present`, режим positive-unlabeled. Положительная принятая
weak-метка имеет mask=true, source=pseudo_label, confidence=null и provenance.
Неизвестное остаётся mask=false/null; не создавать отрицательные классы из
неполной разметки. Нотная проекция означает «роль встречается в подынтервале
этой ноты», а не что роль неизменна на протяжении всей ноты. Полные интервалы
и связи остаются в дополнительном структурированном sidecar.

## Приёмка

Точное соответствие источника/current TRAIN/canonical hash проверяется до
переноса. Используется сохранённый source-row→note binding адаптера, с проверкой
времени, высоты и доступности repair masks. Неоднозначные привязки не принимаются.
Все target IDs разрешаются в существующей CanonicalPiece. Положительных масок
должно быть больше нуля; roundtrip TargetBundle, штатное выравнивание и collator
должны сохранить numeric labels, доступность и source provenance. Raw graph
перед/после прикрепления targets совпадает. Синтетические тесты проверяют
пропуски, разные роли участников, интервалы, продолжения связок и ложные IDs.
Независимые Standards/Spec reviews обязательны для кода.

## Протокол реального выпуска

`EXP-TONAL-RELATIONS-TARGETS-001`, выход
`outputs/tonal_relations_targets_20261006_001/`. Planned record создаётся до
новых реальных аннотаций и чтения canonical payload. Максимум три current TRAIN
произведения, исходный T04-контекст 166 строк; полные canonical pieces допустимы
только для точной привязки и формирования масок. Metadata split manifests можно
читать полностью; TEST/VALIDATION musical payload закрыты. Новых источников,
загрузок и зависимостей нет. CPU serialization/binding/collation only;
GPU, обучение, оценка качества модели и массовая разметка не запускаются.
Legacy не читается и не используется. Старые outputs/cache/records не меняются.

Root владеет выпуском, новым record, CLI/export, документацией и реестром;
Astra ultra — семантическими назначениями; отдельные агенты — binding и
интеграцией targets. Итоговый record закрывается после тестов, ревью и проверки
хешей. Фактическое число доступных целей и исключения публикуются отдельно.

Кодовая база: HEAD `287bf856643f9e555352e1661a7bf0563772178a`, dirty working
tree сохраняется. Следующий этап после выпуска — расширение покрытия целей и
сравнение с независимой разметкой; наличие таргетов не доказывает их точность
или преимущество графовой архитектуры.
