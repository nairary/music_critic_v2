# Ноты, гармонические события и абстрактные функции в одном графе

25 октября 2026. Domain/design clarification по обсуждению пользователя.
Это предложение для спецификации, не изменение действующей схемы, архитектуры
или согласованного экспериментального бюджета.

## Вопрос и основное различие

Пользователь предлагает построить many-to-one связи из группы нот к аккорду,
гармонической функции или более общему объекту, затем использовать обратные
переходы и сохранять иерархию. Нужна модель построения семантического графа
над raw музыкальной основой с разделением экземпляров и типов.

[Query2box](https://arxiv.org/abs/2002.05969) создаёт представление запроса и
оценивает существующих кандидатов на ответ. Relation projection не создаёт
новую музыкальную сущность с собственной идентичностью, временем и участниками.
Поэтому наличие всех исходных нот не мешает Query2box; отсутствующие
гармонические объекты требуют отдельного proposal/discovery механизма.

Проверены код `event_theory_enrichment.py` и связанные контракты. Обогащённая
разметка уже различает harmonies, note_contexts, objects и relations с ID,
интервалами и списками участников. Numerical export сохраняет индексы этих
объектов. Это доступность представления, а не подтверждённое покрытие всех
новых targets или готовый model inference. Первый relation pilot использовал
более узкий note-context readout. Corpus payload/checkpoints не читались.

## Предлагаемые сущности и роли

| Сущность | Пример и идентичность | Что предсказывать |
|---|---|---|
| Note-context | Конкретная нота на точном интервале, внутри analytic view | Участие и роль; удержанная нота может менять роль |
| HarmonyEvent | H17 в данном произведении, interval, view, evidence | Existence, boundaries, участники и их роли |
| Chord structure/type | G7: root/quality/другие доступные компоненты | Поля события или связь с prototype; не смешивать с функцией |
| Functional assignment | Функция H17 относительно tonal context K и view V | `function(H17,K,V)=D`; K может быть неизвестным/предсказанным |
| Process/episode | P5 с source/dissonance/arrival и контекстом | Тип, интервал и явные participant roles |
| Phrase/structural object | F3 с границами и членством | Семантическое группирование, перекрытия и неопределённость |

Условный пример, не наблюдение корпуса:

```text
ноты соль–си–ре–фа в интервале t0..t1
    → реализуют конкретное событие H17
H17 → имеет структуру G7
(H17, контекст до мажора, view V) → имеет функцию доминанты
H17 → разрешается в конкретное событие H18
```

События H17 и H29 могут иметь одинаковые G7/D labels, но остаются разными
экземплярами с разным временем, участниками и зависимостями. Prototype типа
может быть общим. Функция относительно контекста — отдельное утверждение,
а не безусловное равенство «G7 = доминанта».

Важно разделить `sounds_in_context(note,H)` и `chord_member(note,H)`:
попавшая в гармонический интервал нота может быть украшением. Аккорд также
может быть развёрнут во времени, поэтому hard clustering всех одновременных
нот не является достаточным определением HarmonyEvent.

## Что означает many-to-one

Связи множества note-contexts к одному H — incidence между уровнями графа.
Для контекстной принадлежности возможны несколько H-гипотез; целевая cardinality
зависит от view и ontology. Поэтому общая система должна допускать many-to-many,
а не глобально закреплять одну ноту за одним аккордом.

Представление H можно вычислять set aggregation/attention по связанным нотам
и контексту. При этом сохраняются исходные узлы и membership edges. Они не
заменяются одним общим вектором D. Процесс с несколькими участниками разумно
представлять отдельным object/factor node с ролями, не разворачивать безусловно
в clique пар и не смешивать instance P5 с типом отношения `resolves_to`.

## Как появляются новые семантические вершины

Возможные механизмы: кандидаты интервалов на raw временных позициях либо
ограниченный набор object slots, для которых предсказываются existence,
boundaries, memberships и labels. Slots обозначают экземпляры текущего
фрагмента, а не заранее определённые классы «доминанта/тоника».

Как аналогия архитектуры, [DETR](https://www.ecva.net/papers/eccv_2020/papers_ECCV/html/832_ECCV_2020_paper.php)
предсказывает множество объектов через learned object queries и matching;
[Slot Attention](https://proceedings.nips.cc/paper_files/paper/2020/hash/8511df98c02ab60aea1b2356c013bc0f-Abstract.html)
получает набор объектных представлений из низкоуровневых features. Их результат
на визуальных задачах не доказывает обнаружение музыкальных аккордов.
Competitive assignments нельзя автоматически считать правильными при
перекрытиях, украшениях и alternative views. Для музыкальных targets требуется
своя проверяемая постановка.

На обучении размеченные H могут быть targets для proposal/membership/type
heads. На raw-MIDI inference gold H, границы и функции недоступны: их нужно
предсказать. Oracle segmentation остаётся отдельной диагностикой. При неполной
разметке unmatched slot не становится автоматически отрицательным/background,
в отличие от обучения с полным target set. Target availability сохраняет masks.

## Где применять Query2box и NBFNet

После proposal этапа универсум кандидатов содержит наблюдаемые note-contexts,
предсказанные H и другие разрешённые object hypotheses. Их embeddings должны
вычисляться из raw evidence; исходный transductive entity lookup Query2box
не переносится буквально на новые произведения.

Для подтверждённых chord-members n1,n2 можно поставить запрос:

```text
q(H) = chord_member(n1,H) AND chord_member(n2,H)
```

Обучаемые note→harmony projections дают две query boxes в пространстве
гармонических кандидатов; intersection оценивается на тех же H IDs. Дополнительное
ограничение функции требует tonal context и отдельного typed/conditioned
оператора. Это не правило «каждая звучащая нота должна быть chord-member».

Другой запрос ищет конкретный H2, в который разрешается H1 и который имеет
заданную функцию в K. Предсказываются семантические edges/labels между
кандидатами; название chord prototype не подменяет occurrence ID.

NBFNet-inspired query refiner может повторно обращаться к графу нот и H-кандидатов
с marker source/relation. Наблюдаемые temporal/containment edges отличаются
от предсказанных semantic memberships. На inference нельзя незаметно дать
ему gold membership/function edges для восстановления этих же фактов.

Интерфейс NBFNet и box operators ещё требует решения: графовый refiner выдаёт
query-conditioned states/scores, Query2box — компактные query regions. Можно
сравнить отдельные головы или учить согласование; «scores → box» не является
готовой без потерь операцией. Explicit candidate-set baseline нужен для
измерения потерь такого сжатия.

## Три смысла обратного перехода

1. **H→участники данного события.** Обратное чтение membership/incidence:
   возвращаются существующие конкретные note-context IDs и их роли.
2. **Prototype/function→подходящие события.** Retrieval множества H с нужными
   свойствами в данном времени/контексте. Совпавший label не даёт единственный H.
3. **Абстрактная функция→новые ноты.** Conditional generation множества
   допустимых реализаций, с выбором регистра, voicing, длительностей и прочего.
   Это отдельная задача, для которой нет единственной математической inverse.

Само агрегирование many-to-one неинъективно: один вектор D не хранит исходные
ноты однозначно. Транспонирование сохранённой incidence, обучаемый inverse
relation и обращение нейронной функции — три разных действия. Восстановление
нотовых свойств по H может быть auxiliary objective, но не гарантией смысла
латента или доказательством правильной функциональной разметки.

## Какая иерархия сохраняется

Различаются: raw time/containment; instance→type; type→parent type;
семантическое членство event→phrase/process; структурное подчинение в анализе.
Канонические ID, exact intervals, participant roles и view не исчезают при
переходе между уровнями. Все связи не обязаны образовывать одно дерево.
Функция — контекстная роль, не автоматически предок экземпляра в `is_a` tree.

Предложение для первого уточнённого этапа: HarmonyEvent candidates, раздельные
context/core-memberships, chord structure и context-dependent function;
обратный retrieval участников и query intersection на H. Предсказание большого
словаря процессов, редукции и генерация нот — следующие независимые задачи.

## Дорожки, группы партий и ансамбль

Уточнение по следующему обсуждению: область события не была явно закреплена.
Для первого гармонического пути предлагается ensemble scope по доступным
pitched notes в текущем окне; иные дорожки могут давать контекст. Это предложение,
а не уже реализованный H detector или утверждение о scope всех corpus labels.
Source annotation должна сохранить собственную область применимости.

Один общий механизм может строить события для одиночной дорожки, группы
дорожек или ансамбля. В candidate interface следует различать:

```text
event: occurrence_id, exact_interval, analytic_view
participant_scope: какие наблюдаемые части могут участвовать в событии
members: конкретные note-context IDs, роли и masks / predicted scores
context_scope: какие raw данные доступны модели при интерпретации
semantic_fields: структура, функция и другие доступные поля
```

Participant scope — область допустимых участников, не утверждение, что все
звучащие там ноты являются chord-members. Context scope может быть шире:
локальное событие фортепиано интерпретируется с учётом баса другой дорожки,
но бас от этого не становится участником локального события. Все режимы
сравнения должны одинаково объявлять доступный временной/междорожечный контекст.
Для оценки содержательности локальных представлений полезен context-only
контроль: иначе ответ о партии может почти целиком определяться соседями.
Occurrence/candidate ID сохраняется при изменении predicted membership;
численные веса участия не переопределяют идентичность события при каждом шаге.

Условный пример: E–G–B у фортепиано и C у баса. Локальная pitch structure
фортепиано допускает описание Em, а совместный состав — Cmaj7. Это пример
различия областей описания, не правило назначения функций и не corpus fact.
Гармоническая функция верхних голосов не обязана быть самостоятельной Em-функцией;
она может описываться как вклад в общий аккорд. Монофоническую басовую или
мелодическую дорожку не нужно принудительно объявлять последовательностью
полных аккордов: допустимы нейтральные part/group events с маскированными
гармоническими полями, отдельные мотивы и ритмические взаимодействия.

Raw track не равен музыкальному голосу или инструментальной партии; одна
дорожка может быть полифонической, а одна партия распределяться по нескольким
дорожкам. На первом шаге track используется как наблюдаемое техническое
группирование. Музыкальные voice/part/group assignments остаются отдельными
предсказаниями/targets и не выводятся из номера дорожки или MIDI program.

Полезны три независимых измерения: состав участников, временной масштаб и
семантический тип/уровень. Группа бас+фортепиано может пересекаться с группой
фортепиано+мелодия; состав может меняться со временем. Поэтому отношения
поддержки/участия образуют граф с перекрытиями. Вложение множества дорожек само
по себе не устанавливает harmonic parent-child, reduction или `is_a` edge.
При добавлении H/group nodes сохраняются прямые связи с исходными нотами;
ансамблевое событие не обязано вычисляться только через сжатые local H.

Первая ступень: shared features отдельных дорожек и ensemble H там, где scope
разметки это допускает; local H labels обучаются только при их собственной
поддержке. Затем отдельное сравнение небольшого числа group candidates по raw
признакам. Перебор всех подмножеств дорожек не предлагается; learned sparse
grouping — поздняя гипотеза с явным ограничением числа кандидатов. Каждая группа
не требует собственной нейросети: параметры могут быть общими, различаются
состав, время и представление события.

Labels ensemble H нельзя копировать на локальные/групповые события. Наличие
ensemble objects в схеме не подтверждает нужную coverage групп. Task passport
должен установить scope и targets каждого уровня; без них дополнительный
уровень является latent hypothesis, а не проверенной музыкальной интерпретацией.
Полезные engineering checks будущей реализации: идентичность нот через уровни,
перекрывающиеся группы, независимость от произвольной перенумерации track IDs
и отсутствие превращения unknown group targets в negative labels.

## Нерешённые контракты и границы

- Объём поддержанных H-boundaries, memberships и functions по независимым
  works ещё не проверен; не выводится из размера прежнего resolves_to pilot.
- Требуются правила candidate coverage, дубликатов, unknown, several hypotheses
  и empty objects, а также exact interval/view matching.
- Нужно развести type fields и typed edges; отдельный relation на каждую
  тональность/класс не предлагается автоматически.
- Это анализ постановки; схема не мигрировала, default architecture не менялась.
  Код/legacy/data/checkpoints и terminal experiment records не изменялись,
  inference или обучение не запускались.
